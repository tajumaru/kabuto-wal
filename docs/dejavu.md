# カブまるのデジャヴ相場

KABUTO WALにDBを追加せず、既存のJSON Storeを価格改訂・取得履歴・同期ジョブの根拠台帳として利用する。MemWalは長期記憶の保存と意味検索を担当する。数値計算はローカルで決定的に行う。MemWalリレイヤー側は検索インデックス用DBを使用するため、システム全体がDBを一切使わないという意味ではない。

## 確認したAPI

リポジトリにインストール済みの `@mysten-incubation/memwal` は0.1.8。実際の型定義で `MemWal.create`、`remember(text, namespace)`、`waitForRememberJob(jobId)`、`recall({query,namespace,limit})`、`restore` を確認した。アプリのMemoryProviderは既存の保存・完了待ち・検索契約を再利用する。

公式一次資料: https://github.com/MystenLabs/MemWal/blob/dev/docs/sdk/api-reference.md

rememberのjob_idは受付を示す。blob_idが確認できた場合だけsyncedとする。受付済みジョブを再送しない。受付不明はuncertainとして止める。実アカウントへの書き込みは検証では行わず、プロバイダーのテスト代替で確認する。

## 特徴量とスコア

調整済みO/H/L/Cと調整済み出来高の20営業日（20本）を使用する。終値形状は初日=100、日次リターンは19本、ローソク足は実体・上ヒゲ・下ヒゲを始値で割る。出来高は窓平均比、変動率はリターンの標準偏差。

距離は各系列のRMS差を固定尺度で割り、価格形状35%、リターン25%、ローソク足20%、出来高15%、変動率5%で加算する。固定尺度は順に5指数ポイント、2%、2%、1倍、2%。スコアは100×exp(-距離)。完全一致は100点。経験的な尺度であり、校正された投資確率ではない。MemWalのcosine distanceとは別物。

欠損・非有限数・不正OHLC・日付重複・カレンダー欠落・異なる取得調整系列は補間せず除外する。現実の日足が不足しているときにデモへフォールバックしない。

## 時間と未来混入の防止

過去基準日はその日23:59:59.999 JSTを知識の締切とし、availableAtが締切以前の取得記録を日ごとに選ぶ。最新検索は検索実行時点を締切とする。取得時点を偽って履歴を過去に遡らせない。今日初めて取得した過去価格は、過去基準日の当時既知データとしては利用できない。

価格内容が同じでも取得時刻・系列が変わった観測は改訂ファイルとして保持する。既存の旧改訂JSONも読み込めるが、保存されなかった過去観測を再構築はできない。

候補は20本の比較窓とその後20本の結果を合わせた40営業日が連続し、結果の最終日も比較元の開始日より前であることを要求する。候補同士も40営業日以上離し、結果窓の重複を除く。順位計算は候補窓の特徴量だけを使う。その後の実績は表示専用。予測・バックテストの既存neighbors-v1とは別エンジンとして維持する。

## UIと記憶

既存 `/similar` 画面をデジャヴ相場に更新。横軸0が各窓の最終日、左側20営業日を初日100で比較し、右側は過去候補のみその後20営業日を表示。上位5件のスコア、特徴量距離、1/5/20営業日後実績を表示する。カブまる通知は同じ結果IDで重複を防ぐ。

`POST /api/dejavu/save` による明示保存。検索GETは通知だけを記録し、長期記憶は追加しない。記憶は検索結果、版、重み、価格改訂ID、基準日、取得締切、mode/sourceを含むJSON。namespaceは `stock-memory:dejavu:v1:{mode}:{code}`。ローカルJSONはオフライン根拠と再同期用台帳で、MemWalを置き換える意味検索DBではない。

実データの外部保存・検索は既存 `ALLOW_MARKET_DATA_TO_MEMWAL=true` とMemWal本人/delegate確認を条件とする。デモは接続設定に関係なくローカルのみ。保存表示はpending/accepted/syncedを区別し、接続失敗時はローカル保存を維持する。既存の取得ジョブでも保留記憶を再同期できる。

`GET /api/dejavu/memories?code=...&asOf=...` はMemWal意味検索結果とローカル台帳を統合する。JSONを構造検証し、mode・銘柄・namespace・結果ID・記憶作成時点・基準日を検証する。後日保存した記憶を過去検索に混入させない。意味検索は全件列挙ではなく、返却された最大20候補の検索結果である。保存日時による制約のため過去基準日で今保存しても、その過去時点の記憶検索には出ない。
