# 予測精度検証3.0

調査起点：最新main `1042be9`（作業開始時fetch、origin/mainとの差分0、未コミット変更なし）。

## 調査と変更

従来の `bottom-scout-accuracy.ts` は、ページに含まれる最大5分析だけを評価し、重複除外もページ内に限定していた。3.0では選択したデータ区分の全予測manifestを検証して集計し、明細だけをページングする。分析IDの絞り込みも明細にのみ作用する。

- `packages/core/scout-accuracy.ts`：全履歴の重複排除、Wilson 95%区間、累積件数・相場環境・説明のレスポンス型。
- `apps/api/src/bottom-scout-accuracy.ts`：全履歴集計、全関連評価原本のhash・参照検証、ページ別明細、かぶまるの根拠付き件数説明。集計方式は `scout-accuracy-v2`。予測・評価の採点方式は変更しない。
- `apps/api/src/bottom-scout-journal.ts`：保存しない再計算オプション。既存の通常評価の保存動作を維持。
- `apps/api/src/scout-accuracy-cache.ts`：最大4エントリ・最長60秒のメモリキャッシュ。利用したJSONの**内容hashとディレクトリ一覧を毎回照合**。未来の観測・期限に達する前に失効。世代番号やTTLだけでは原本改変を見逃すため、それらだけのキャッシュは採用しない。追加・欠損・改変・価格更新で再計算する。
- `apps/api/src/scout-market-regime.ts`：予測時点の取得締切で市場指標系列を再構成し、上昇・下落・横ばい・分類不能を分類。
- `scripts/diagnose-scout-accuracy.ts`：初期化・writer lock・書き込みを禁止した診断。許可した保存パスに限定し、root外へのシンボリックリンクを拒否。原本payloadや例外の生文字列、設定・鍵は出力しない。
- `apps/web/src/ScoutAccuracy.tsx`：全履歴の件数、区間、相場環境、かぶまるの説明。既存の明細折りたたみ・320px対応・URL状態・スクロール復元を維持。
- `tests/scout-accuracy-cumulative.test.ts`、`tests/scout-market-regime.test.ts`、`tests/e2e/scout-accuracy.spec.ts`：下記検証。

## 集計定義

DEMO / J-Quantsと、当日基準 / 過去・遅延データ研究を別々に集計する。後者は既存のrecordingModeを維持し、過去原本の区分を書き換えない。

同一方式・銘柄・基準日の予測は、全履歴で予測日時が最も早いものを採用する。同時刻はforecastIdの辞書順で決定する。順位も最初の原本に固定され、後日の順位でTOP3/5/10を有利に変更しない。予測manifestのない古い分析を後付けで予測に変換しない。

的中は期限後の調整終値リターンが0%超。横ばいは不的中。評価待ち・評価不能は分母から除く。期限は固定済みの市場営業日カレンダーを使い、元の予測価格を更新しない。平均リターンと、同じ評価可能ペアだけのベンチマーク超過リターンを分ける。設定した比較銘柄はTOPIXとは限らない。

Wilson区間の根拠：[NIST 7.2.4.1 Confidence intervals](https://www.itl.nist.gov/div898/handbook/prc/section2/prc241.htm)。独立な二項標本を仮定した**参考区間**で、銘柄・連続日・重複評価窓の相関補正は行わない。将来の上昇確率、校正済み予測確率、運用利益の保証ではない。評価済み20件未満では少数標本を明示する。取引費用・配当・約定は未考慮。

## 相場環境と設定

新規の必須環境変数はない。任意の `SCOUT_MARKET_REGIME_INDEX_CODE` は、**保存済み市場指標のprovider codeであると利用者が確認したもの**に限る。予測manifestがすでに固定している `benchmarkCode` と一致する場合のみ使用する。通常の個別株を市場全体として自動解釈しない。未設定・不一致・75営業日の連続データ不足・revision矛盾・調整系列混在は分類不能とする。

判定方式 `market-regime-v1`：予測時点で利用可能な75営業日の調整終値を使用。終値が75日平均の102%超かつ25日平均が75日平均超なら上昇。98%未満かつ25日平均が75日平均未満なら下落。それ以外は横ばい。未来revisionは除外し、同順位矛盾は拒否する。cutoff・入力hash・revision IDを派生診断に保持する。

これは保存済みの当時利用可能データから行う**後付けの派生診断**であり、当初から市場環境を予測根拠として保存していたとは表示しない。予測原本に分類を追記しない。指標が保存されていなければ追加取得せず分類不能を表示する。

rtk proxy pnpm exec tsx scripts/diagnose-scout-accuracy.ts live <承認された保存先>

Service.initは呼ばず、settings・.env・MemWal・Sui・外部APIを使用しない。保存先が存在しない／アクセスできない場合、status=unconfirmed・counts=nullとする。既存hash不整合時も成績を成功扱いせず診断未完了とする。保存済みデータだけで再計算し、評価原本の新規保存は0件。再計算で得たIDを保存済み原本と偽らない。

今回確認した `data/demo` は当日基準・研究とも予測manifest 0件。これはDEMO保存先の結果であり、実運用の0件を意味しない。`data/personal` / `data/live` はAGENTS.mdの実利用者データ読取禁止との調整のため、限定読取許可を依頼した。許可未取得の間は未確認。本番配置先・実J-Quants取得・実データ評価保存も未検証。許可なく本番書き込み・追加取得・外部送信は行わない。

## 人工データによる検証と性能

- 7分析原本・2銘柄がページをまたぐfixture：14予測から全履歴で12重複を除外、2件を採用。どのページでも同じ累積成績、最新ページの重複記録は集計しない。
- 読取専用診断の前後でファイル一覧不変、store.writeの呼び出し0、fetch呼び出し0。不存在rootを0件と報告しない。
- 95%区間：未評価、全勝、全敗、5/10の既知値、不正件数を検証。
- 市場環境：上昇・下落・横ばい、入力逆順、未来revision、欠損、同順位矛盾、指標未指定を検証。
- 既存の評価ID改変・営業日改変・revision順序・不足データ・固定TOP10の回帰テストを維持。
- 100分析原本・1銘柄を意図的に繰り返した人工fixtureの単回計測：初回692.16ms、キャッシュ再表示226.60ms、明細1原本のレスポンス30,237 bytes。系列再構成の呼び出しは再表示時0、価格更新後は失効。これは同じ新実装のcold/warm比較であり、旧実装との改善率や実市場性能ではない。
- 本番ビルドの答え合わせJS：18.50KB（gzip 6.68KB）。ブラウザ初期表示の時間分布・iPhone実機・実市場大規模履歴の性能は未計測。

全履歴の初回集計とキャッシュ検証のI/Oは履歴件数に比例する。長期保存・数万件規模での一定応答時間は保証しない。価格系列のリクエスト内共有、内容検証済みキャッシュ、ページごとの明細・振り返り生成で負荷を抑える。より大きい実データでの診断後に、変更検出を維持できる派生索引を検討する。
