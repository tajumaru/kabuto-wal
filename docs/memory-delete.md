# MemWalからの記憶削除

「記憶一覧」の「無効化」はアプリ内の参照を停止する操作です。新しい「MemWalから削除」は、Security Delete APIで該当記憶のblobを削除する別の操作です。

## 利用条件と手順

- 実モード・本人ログイン済みで利用します。
- `OWNER_ADDRESS` と `MEMWAL_NETWORK=mainnet` または `testnet` を設定します。予測アンカーの `SUI_NETWORK` と別にMemWal側のネットワークを使います。
- `MEMWAL_SERVER_URL` のサーバーがSecurity Delete APIに対応し、保存済みblobがそのサーバーの削除対象である必要があります。未対応・対象外の場合は削除を止めます。
- 同期完了してblob IDを確認できた記憶にだけ削除ボタンを有効にします。
- 対象の内容・blob IDを確認し、チェックを入れ、所有者ウォレットを接続します。本人確認のメッセージ署名と削除取引の署名が必要です。所有者の秘密鍵をアプリへ入力する必要はありません。

削除APIには選択した1件のblob IDだけを送り、`mode: all`は使用しません。削除が完了したことを確認した後、ローカル記憶は残して利用停止にします。再有効化はローカル参照の再開だけで、削除済みblobの自動再同期は行いません。訂正で新しい記憶を作成した場合は別の記憶として扱います。

## 中止・通信障害

未署名の準備は「署名前の削除を中止」で取り消せます。削除送信前にバッチIDと処理状態を保存し、送信後に通信が切れた場合は「削除結果を確認」を使います。実行中の対象を新しいバッチで再送しません。再起動・画面再読み込み後も、同じバッチの結果を再認証して確認できます。Bearerトークン・署名はディスクに保存しません。

準備レスポンス自体が失われた場合は取引署名を行わず、削除は送信しません。サーバー側に準備が残る場合があるため、期限切れを待つか公式ダッシュボードで確認してください。

## 制限と確認範囲

Security Delete APIは、MemWalの旧V1データベースで追跡されているWalrus Blobオブジェクト専用です。同期完了・blob IDありでも、このAPIで削除できるとは限りません。公式手順に沿って準備APIを呼ぶ前に全状態の対象一覧をページごとに照合し、対象blobが `deletable` の場合だけ準備します。対象外の場合に別のblobへ置き換えたり、削除完了扱いにしたりしません。準備時に空の結果になった場合も再照合します。一覧にない場合、保存先・所有者の違い・API非対応の保存形式を候補として表示し、新形式と断定しません。MemWalの既知のエラーコードとHTTP状態を保って返し、認証・ガス不足・対象外などを区別します。「無効化」はアプリ内の参照停止であり、MemWalからの削除ではありません。

画面の署名は2段階です。最初の `MemWal security deletion auth` メッセージ署名は本人確認のみで、削除は実行しません。対象照合と準備に成功した場合だけ削除取引の署名を求めます。画面に各段階の進行状況を表示します。

Walrus上の削除は、第三者のコピーやキャッシュの消去までは保証しません。アプリ内の元の記録、会話、監査記録、既存バックアップも削除対象外です。

模擬APIで1件選択・完了確認・通信断・重複防止・未署名取消・再同期防止を検証し、ブラウザで確認画面と署名前の操作制限を検証します。実際の記憶削除・実ウォレット署名・利用先の対象blob適格性はこの開発検証では確認しません。
