# MemWalの同期・削除の復旧

対象SDKは `@mysten-incubation/memwal` 0.1.8。保存・削除・索引リセットは別の状態として扱う。

## 保存

- 送信前に受付キー、送信本文、名前空間、接続先bindingを永続化する。通信結果不明の場合は同じキー・本文で再試行し、新規書き込みを重複作成しない。
- 既知のjobはSDKの `getRememberStatus()` で追跡する。`failed` は確定失敗、`not_found` は結果不明として、新しい受付キーでの自動再送を止める。
- 確定失敗は記憶の「保存データの詳細」から次回同期の再試行を予約できる。APIは所有者ログイン、外部送信許可、削除・リセット状態、遠隔jobの確定失敗を再確認する。
- 旧データに受付キーがなく結果不明の場合は自動再送しない。旧レシートの接続先はjobのowner・namespace・blob IDが一致した場合だけ関連付ける。jobが失われている場合は推測で移行しない。
- 同期結果を件数で集計し、株価処理の成功とは別に同期未完了を表示する。外部エラー本文はローカルにそのまま保存しない。

## blob削除

- 送信中の状態で中断した場合は、まず削除結果を確認する。
- 未確認のままなら「同じ削除取引に署名して再送」を利用できる。保存済みbytesとdigest、plan ID、所有者署名を照合し、同じ取引だけを再送する。署名自体は永続化しない。
- 結果不明の取引を新しい削除取引として作り直さない。完了扱いには対象blobの削除イベントが必要。
- 類似検索の上位50件で見つからない状態は `not_observed` と記録する。全索引からの消失とは表示しない。

## 検索索引リセット

- 遠隔操作の前に再送防止を記録し、各記憶に `searchResetState`（pending / uncertain / completed）を残す。
- 中断時は同じ対象画面の「対象を確認」で再照合する。完了済みの区分は再実行せず、未完了の区分は現在の件数を表示して再確認・再開する。すでに0件なら再削除しない。
- 結果不明の再送防止を自動解除しない。ローカルの記録は保持する。検索索引リセットは名前空間全体に作用し、Walrus原本の削除ではない。

## Mainnetと取得

- アプリRPCとSDKがRelayer設定から利用するRPCのチェーン識別子を検証する。gRPCのgenesis digestとJSON-RPCの短形式を扱う。RPC URLにはHTTPSを要求し、URL内の認証情報を拒否する。
- 「MemWal owner・delegate確認」はSDKのrecallまで実施し、SEAL認証を含む読み取りを確認する。
- デジャヴ候補は遠隔結果よりローカルの無効化・削除状態を優先する。

参考: [公式SDKのchain identifier説明](https://mystenlabs.github.io/sui/sui_sdk/digests/index.html)、[Suiのネットワーク](https://docs.sui.io/develop/sui-architecture/networks)。認証・受付キー・SEALセッションの実装はインストール済みSDKの `dist/memwal.js` と照合している。

本番アカウントへの新規保存・削除・索引リセット、既存データの一括移行は検証のために実施しない。テストは一時ディレクトリと偽の外部応答を使用する。
